# Mozambique gazetteer

Two data files, both derived from current public sources. They are country-pack data,
not patient data.

## `admin_units.csv`

From **OCHA COD-AB v02, Mozambique** (`moz_admin_boundaries.xlsx`):

- valid for use 2025-01-01; dataset reviewed 2026-03-10
- Admin 1: 11 província
- Admin 2: 161 distrito
- Admin 3: 457 posto administrativo
- Admin 4: 1712 localidade
- one point per unit with `x_coord`/`y_coord` (the `moz_adminpoints` sheet)
- P-codes: ADM1 and ADM2 supplied by INE; ADM3 and ADM4 generated by OCHA because
  no official codes exist. Treat ADM3/ADM4 codes as stable internal join keys, not
  official national codes.
- Licence/use: OCHA COD-AB is published for humanitarian use. Attribute OCHA and
  INE; do not present ADM3/ADM4 p-codes as official.

## `facilities.csv`

From the **Mozambique Master Health Facility List** (HDX, source SIS-MA):

- 1590 facilities; 1589 with a coordinate
- columns: name, classification, province, district, district_code, facility_code, lat, lon
- the source sheet says `_Date_: unknown`; the list is dated and should be treated as
  a starting point, not an authoritative current register
- the exported LAT/LON values are malformed in places (decimal point lost); the build
  script recovers them by digit count and validates against Mozambique bounds
- facility names match the card's "Unidade Sanitária" examples: Impiri (Balama),
  Bilibiza (Chiure), Namogelia (Chiure), Montepuez (Montepuez)

## What the card fields mean

| Card label | Level |
|---|---|
| Distrito | ADM2 district |
| Localidade | ADM3 administrative post (e.g. Namogelia in Chiúre) |
| Unidade Sanitária / Aldeia | health facility (MFL) or ADM4 locality/village |
| Provincia | not printed; infer from district (all 161 ADM2 names are unique) |

`Impiri` is a health facility in Balama and not an ADM4; `Bilibiza` is both an ADM4
under Namogelia and a health facility in Chiure. That is why the resolver must try
the facility and the ADM4, not assume one.

## Build

```bash
python tools/build_gazetteer.py \
  --cod /path/to/moz_admin_boundaries.xlsx \
  --mfl /path/to/mfl.xlsx
```

The source XLSX files are not committed. The derived CSVs are.

## Cautions

- The MFL is incomplete: about 1590 facilities against roughly 1770 in national
  reporting, and its date is unknown. Use it for a first candidate, then validate.
- The MFL district codes are not the HDX p-codes. Join on names and context, not
  on codes.
- The card's "Localidade" is not always an ADM3: `Impiri` is a facility. The
  resolver should return candidates from both levels and let the user confirm.
- OSM/Nominatim and Photon coverage is uneven. In a spot check, Nominatim found
  Impiri and Namogelia but not Bilibiza in Chiure; Photon found Impiri and the
  Impiri health centre, but placed Bilibiza in Quissanga. The local gazetteer and
  the map picker are the reliable path.
