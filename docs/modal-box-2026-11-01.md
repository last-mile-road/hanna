# The HANNA box on Modal — one L40S, all readers (2026-11-01)
`deploy/modal_box.py`, app `hanna-box`, workspace `ariedk`. One L40S (or RTX-PRO-6000
/ A100-80GB as fallback), one container, one authenticated proxy.

**Status: working.** Cold start 387 s. First card (form16) through both readers:
MinerU **25.6 s**, 3,641 chars, one HTML table with the header row and NIL
`KDR-55-7210` read correctly; 9B answered "Samuel Alberto João" from the full card
in **26.5 s**, using 575 completion tokens on its reasoning trace. GPU at 32.3 GiB of
46.1 in use while warm — 14 GiB of headroom.

## What runs

| port | service | budget | role |
|---|---|---|---|
| 8000 | vLLM `Qwen/Qwen3.5-9B` (`hanna-9b`) | util 0.55, 32k ctx, max_pixels 2M, image cache 0 | text blocks, dips, hand/feet, treatment |
| 8003 | vLLM `MinerU2.5-Pro-2605-1.2B` (`mineru-vlm`) | util 0.35 of what is left | MinerU's VLM |
| 8002 | `mineru-api --tier standard` | CPU + ~2 GB | layout, tables, tick columns |

PaddleOCR-VL is in the code behind `HANNA_BOX_PADDLE=1`, off by default. On a 46 GiB
card the 9B plus Paddle leave 5.7 GiB; Paddle and MinerU's VLM do not both fit.

`scaledown_window=300` — five minutes of idle after the last request, then zero.
`timeout=2h` as a cost backstop. `max_containers=1`, `max_inputs=8`.

## Six boots, six lessons

1. **`--disable-log-requests` no longer exists** in vLLM's CLI, and `mineru[full]`
   had pulled vLLM down to 0.22.1. Fixed by installing `mineru[torch]` and pinning
   `vllm==0.30.0` last.
2. **`import torch` broke with `undefined symbol: ncclCommWindowDeregister`** — the
   GPU Paddle wheel puts nvidia-nccl-cu12 2.25.1 over torch's cu13 NCCL. Fixed by
   using the CPU Paddle wheel; the VLM half still runs on the GPU.
3. **A function that blocks in `uvicorn.run()` never serves.** With `@modal.web_server`
   nothing answered on 8080 for 600 s. `@modal.asgi_app` returning the app works
   (34 s to first 200).
4. **vLLM 0.30 reads `gpu_memory_utilization` as a fraction of free memory at engine
   init**, not of total VRAM, and refuses to start if that is below free. So engines
   must start in sequence, each sized against what is actually left.
5. **MinerU's own VLM budget is not configurable** (0.13 of what is free). Next to
   the 9B that is less than its weights, so it dies. Its VLM is served as a separate
   vLLM and `mineru-api` points at it with `--vlm-server-url` — the hosted-service path.
6. **A 401 from `VLLM_API_KEY` in the environment** made Paddle's port look unready
   for 15 minutes. vLLM reads the key from the environment as well as `--api-key`.
7. **`gpu_memory_utilization` sizes KV cache from a fraction, not from need.** The 9B
   asked 24.4 GiB and MinerU's VLM 15.6 GiB — 11.1 GiB of that an idle KV cache for a
   1.2B model at 8k — leaving 4.4 GiB, and the first real request killed the container.
   Both engines now pass `--kv-cache-memory-bytes` (6 GiB and 2 GiB), which skips the
   fraction entirely and leaves 14 GiB spare.
8. **The 9B reasons before answering.** On a full card it spent 575 completion tokens
   and 26.5 s to return a name it had read in the first seconds. Block crops will be
   faster, but the pipeline's `reasoning_effort` setting has to be carried into the
   request or the box pays that cost on every call.

MinerU 4.1.3 also moved its health check to `/v1/health`, dropped
`--allow-local-source` and `--no-flash`, and replaced `/v1/file_parse` with a
task-plus-upload protocol. The proxy uses MinerU's own client
(`mineru.parser.api_client.MinerUApiParser`), not hand-rolled HTTP.

## Reader choice

MinerU, not Paddle. Evidence in `readers-comparison-2026-10-30.md`: disability is a
tie (98/98 both), nerve is MinerU 84/84 against 48/72, and Paddle's only unique win is
one treatment cell (22/23 against the 9B's 21/23). Keeping Paddle would cost five
nerve cells; keeping MinerU costs one treatment cell.

## Run it

```bash
# deploy (image build is cached after the first time)
MODAL_PROFILE=hanna ~/.local/share/hanna/modal-venv/bin/modal deploy deploy/modal_box.py

# one card through the 9B and MinerU; waits for the cold start
export HANNA_KEY=...
python3 deploy/box_smoke.py \
  --url https://ariedk--hanna-box-box.us-east.modal.run \
  --card ../hanna_archive/versions/v4_hanna3_2025-2026/test_forms/form16.jpg

# diagnostics while warm (needs the key)
curl -s -H "X-HANNA-Key: $HANNA_KEY" https://ariedk--hanna-box-box.us-east.modal.run/ready | jq
```

`/ready` returns the GPU model, per-engine ready time, the last 15 log lines of each
engine, and any `problem` the engine reported. `/warm` is the cheap one for a capture
page: 200 when everything is loaded, 202 with a per-engine map until then.

## Cost

L40S $1.95/h, per-second billing. A sitting of seven cards is roughly 5–7 min boot +
9 min of cards + 5 min idle hold ≈ 20 min ≈ $0.65. The build above cost about $2 in
failed boots, all of it diagnosable from the kept logs.

## 9B tuning (2026-11-01, evening)

Taken from the [Qwen3.5-9B model card](https://huggingface.co/Qwen/Qwen3.5-9B):

| what | why | effect |
|---|---|---|
| `chat_template_kwargs: {"enable_thinking": false}` injected at the proxy | the card's instruct route; thinking is on by default | full card 26.5 s → 14.8 s, 575 → ~0 reasoning tokens |
| `--reasoning-parser qwen3` | the card's vLLM serving command; keeps ` thinking` parseable if a caller re-enables it | none while thinking is off |
| `--speculative-config '{"method":"qwen3_next_mtp","num_speculative_tokens":2}'` | the card recommends MTP speculative decoding on vLLM | not isolated (no A/B) |
| instruct sampling variant (temp 0.7 / top_p 0.8) | the card's "instruct, general" set | 46/53 vs 45/53 on form16 — noise, and slower; greedy stays default |

Not applied: 262k context (KV cache would not fit and crops are small), 32k output
(irrelevant for extraction), YaRN (only for >262k).
