# Self-hosted 9B on Modal — what it took, and where it stands

## The failure that cost the day

`Engine core initialization failed` was not a GPU or capacity problem. vLLM's default
sampling path **JIT-builds a FlashInfer kernel with nvcc inside the container**, and that
build fails:

```
ninja: build stopped: subcommand failed.
RuntimeError: Engine core initialization failed.
```

Fix: `VLLM_USE_FLASHINFER_SAMPLER=0` in the image environment. This is very likely the same
cause as MinerU's L4 failure — MinerU uses vLLM too, and its log ended with the same message.

## What works

- One vLLM server, one `@modal.web_server`, L40S, fp16, `--api-key`.
- `/v1/models` answered **200 after 258 s cold start**.
- Engine init: **152 s** (of which 29 s `torch.compile`).
- Warm requests answer immediately (`/v1/models` in 48 ms execution).

## Image size versus context

A 4080×3072 card tokenises to **12,330 image tokens**, which exceeded the first 8k window.
Now `--max-model-len 32768` with `--mm-processor-kwargs '{"max_pixels": 4000000}'`.

The pipeline sends **block crops**, not the full card, so production calls are far smaller;
the full card is the worst case.

## Rules learned

1. Test with the Modal **client**, not curl: a web endpoint that is starting or being retried
   returns 303 with an attempt token, and curl reads that as failure while the logs show
   uvicorn running.
2. `modal app stop <app> -y` (no TTY abort), and a stopped app returns 404 until redeployed.
3. A warm container with an old config keeps answering the old config — stop before
   measuring a changed flag.
4. One model per app; the consolidated box (two servers + proxy) never answered.
